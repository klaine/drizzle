# Drizzle: agent notes

Granular `sound_generator` (Schwung API v2), module id `drizzle`. Read [README.md](README.md) for
the product and [plan/README.md](plan/README.md) for the spec. This file covers working on the code.

## Commands

```sh
scripts/build.sh              # gen --check, native tests (fast and slow read paths), contract, dsp.so, check_so.py, package, web
scripts/build.sh --gen        # run tools/gen/gen.py first (after editing tools/gen/params.py or presets/factory)
scripts/build.sh --bench      # also the native CPU benchmark
scripts/build.sh --render     # also one demo WAV per factory patch in build/demo
scripts/build.sh --profile    # dsp.so with the read-only cpu_us key (render time, not for release)
scripts/build_web.sh          # drizzle.wasm, build/site (python3 -m http.server -d build/site 8765), build/drizzle.html
scripts/pages.sh [--push]     # build/drizzle.html as index.html on the `pages` branch (build.sh runs it, without --push)
scripts/deploy.sh [host]      # staged install on a Move; scripts/logs.sh follows the debug log
```
zig comes from `PATH`, `$ZIG` or `pip install ziglang`.

## Status
M1 done. Milestones are in `plan/14-roadmap.md`; `plan/16-implementation-status.md` records what's
built, measured, inert and different from the spec: update it when that changes.

## Where things come from
- **Parameters, pages, categories:** `tools/gen/params.py`. `gen.py` writes `src/dsp/params_gen.*`,
  `contract_gen.c`, `windows_gen.c`, `factory_presets.c` and `build/ui/*.json`. Pages carry a
  milestone and appear in `ui_hierarchy` once `MILESTONE` reaches it.
- **Factory patches:** `presets/factory/*.json`, only the values that differ from INIT. The browser
  build's "Patch JSON" button writes one.
- **Browser:** `web/` (the page, worklet and wasm host) is Drizzle's own; the Remote UI on the Move
  (`src/web/`, with the shared preset browser) comes with M4.

## Spec rules
- `plan/` is the spec; once code exists, the code is the source of truth. If they disagree, fix one
  of them in the same change.
- **VERIFY** in `plan/` marks assumptions about the device or host; `plan/15` lists them with the
  milestone that answers each. Record answers and decisions there.
- `BACKLOG.md` lists features beyond the `plan/14` milestones.

## Siblings (templates)
- **Crest** (`klaine/crest`) is the primary template: Zig build, `tools/gen` codegen with `--check`,
  contract validator, oscillators, filter, effects, canvas/cards UI, Remote UI, single-file web
  build, worker-thread file loader (`src/dsp/peak_bank.c`).
- **Amino** (`klaine/amino`) supplies the wavetables (`tools/wavegen`), Flavour, the pressure page,
  the "via" matrix and golden tests over every factory patch. Its `src/web/presetbrowser.js`,
  `presetdrawer.js` and `presetbrowser.css` are canonical: Drizzle carries byte-identical copies.
- Effects come from Amino's `src/dsp/fx.c` by way of Crest: a fix in one may apply to the others.

## Rules carried over (they apply from the first line of code)
- **Flags:** `-Wall -Wextra -Werror -Wshadow -Wdouble-promotion`, and `-ffast-math
  -fno-finite-math-only` on device and in tests alike (the NaN guard depends on it). Native tests
  run under UBSan.
- **Realtime:** the audio thread does no I/O, no allocation, no logging and no unbounded work. The
  tape renders in fixed chunks per block. Only the sample loader thread (M5) touches files.
- **Tests:** `-DDRZ_TEST` tags every ring slot with its absolute position, and the grain loop checks
  every point it reads; keep that check when changing the read paths.
- **Generated files** (`params_gen.*`, `contract_gen.c`, `factory_presets.c`, `wavetables.c`,
  `windows_gen.c`, `build/ui/*.json`) come from `tools/gen/params.py` via `gen.py`; never hand-edit
  them. The build runs `gen.py --check`.
- **Golden audio** covers every factory patch. An intended sound change needs `--write` and the
  reason in the change description; never rewrite it to make a failure go away.
- **Third-party material:** wavetables follow Amino's `docs/07` rules; samples must be our own or
  CC0, credited in `THIRD_PARTY_NOTICES.md`. No commercial instrument names in user-facing text.
- **`pages` branch:** generated by `scripts/pages.sh`, never committed to by hand.
